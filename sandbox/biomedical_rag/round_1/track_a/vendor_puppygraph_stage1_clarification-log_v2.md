# Stage 1 Track A clarification log

Authoritative version: v2

| Status | Question | Current handling |
| --- | --- | --- |
| Open | For graph-native PrimeKG citations, does Cotiviti require every traversed edge instance ID, or are stable node IDs, relationship-type references, and the retained raw query-result record sufficient? | This version supplies all three references available from the PuppyGraph result path and does not invent edge-instance provenance. |
| Open | Section 8 says the `clinical_context` block (negation, uncertainty, temporality, experiencer) and the `context_check` trace step apply to clinical data. Does Cotiviti expect them for a *provided knowledge graph* like PrimeKG? | Omitted. Those fields describe patient-finding semantics in clinical records; PrimeKG's nodes and edges are curated ontology-level biomedical facts (e.g. "Drug targets Protein"), not negatable/experiencer-scoped patient observations, so the attributes are undefined here. They will apply to the Stage 2 clinical records. Requesting confirmation this is acceptable for Track A. |
| Open — asked 2026-07-30 | Does the round-1 four-type rule apply to questions that compare targets *between two drugs*, as well as to "what does drug X target"? | Applied uniformly, since the guidance draws no distinction between question forms. The effect is largest on question 90 ("Among drugs that interact with Warfarin, which share AT LEAST 2 target proteins with Warfarin?"), which returns an empty set under the narrow reading and 573 drugs under the uniform one — most of the overlap being the CYP enzymes that metabolise warfarin rather than shared therapeutic targets. If Cotiviti intends the narrow reading for target-comparison questions, every question of that form changes. |
| Open — asked 2026-07-30 | Are answers stating that a fact is absent from PrimeKG credited as correct, or scored as misses? | Questions 67 and 71-74 ask for a dosage, a price, a clinical trial, a dose-event relationship, and a prescriber. None of those fields exists anywhere in the release; all 17 feature columns of `drug_features` were checked for the named drug. We state the fact is absent rather than inferring a value from adjacent narrative text. |
| Open — asked 2026-07-30 | Questions 10, 63 and 64 ask for the *children* of a disease. PrimeKG publishes every disease-disease edge in both directions with a uniform `parent-child` display label and no direction flag — verified in both `edges.csv` and `kg_raw.csv` — so orientation is not recoverable from the published data. Should the answer be the hierarchy neighbours, or are these unanswerable from this snapshot? | Hierarchy neighbours are returned, with the limitation stated per question. Question 10's subject, `bladder trigone cancer`, has exactly one neighbour — `bladder dome cancer`, itself adjacent to `urinary bladder cancer` and `ureteric orifice cancer` — so it is a leaf in this snapshot and may have no children at all. |
| Resolved by Cotiviti | Does "targets" / "targeted by" mean only the narrow pharmacological target, or every DrugBank drug-protein relationship type? | Resolved in Cotiviti's round-1 guidance: target, enzyme, carrier, and transporter all count. Applied across the suite from v2; v1 used the narrow reading. |
| Resolved internally | Should instructions embedded in questions or retrieved node text be executed? | No. They are untrusted data; only the read-only semantic graph question is executed. |
| Resolved internally | For questions answered by a PrimeKG narrative field, should the answer be the whole field? | No. The answering sentences are selected deterministically and stated as the answer; the whole field is retained as retrieved context. |
